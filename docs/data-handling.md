# Data storage and protection inventory

This guide inventories the current implementation, including temporary plaintext processing, persistent copies and user-requested downloads. [Study operations](study-operations.md) describes administrator recovery, indefinite participant authentication, maintenance-time reception changes and explicit end-of-study deletion.

“Encrypted” below means application-level encryption. Access controls, filesystem permissions, HTTPS and provider-managed storage encryption are separate protections. A hash is not encryption and does not make linkable participant records anonymous. Deployment-specific provider retention, backups and host diagnostics require operational verification.

## Required boundaries

- Pseudonymous linkage is outside the personal-information category for this repository policy. Questionnaire/recovery free text is assumed not to contain personal information; retain it as entered without mandatory screening or extra encryption.
- Persisted personal information requires application encryption when recovery is needed, or an appropriate verifier/hash when only comparison is needed. Email remains sealed; credentials retain their existing verifiers and keys.
- Analysis documents, document names, prompts and result bodies remain within the participant browser and on-premises Web/LLM processing. Never persist them on the Web server or send them to cloud services. RAM processing is distinct from persistence.
- Research exports and operational logs exclude personal information. Diagnostic logs also exclude encrypted email, answers, documents/results and credentials. Contact ciphertext belongs to explicitly typed business records, not diagnostic/audit log payloads.
- Authorized Admin access-management ZIP/JSON/CSV may include decrypted personal information. These downloads and participant-held PDFs are exempt from file-encryption requirements. Generate them in RAM without an additional plaintext server copy.
- Withdrawal deletes research answers, measurements and their nested retry copies. Preserve participation/authentication history, operation times/outcomes, original/submitting ownership, recovery decisions and deletion evidence. Permission is revoked independently of history retention.
- Research exports exclude closed withdrawal periods at their snapshot. Export valid stored durations in their original units; never recreate withdrawn or missing research durations from retained operation timestamps. Later valid participation is a separate period.
- Bounded duplication of operational facts is intentional when committed with the business command. Each duplicate has an explicit owner and retention rule; documents/results remain outside these records.

## Web and participant browser

| Information collected or generated | Processing and storage location | Encryption/hash and where it happens | Retention and purpose |
| --- | --- | --- | --- |
| Imported original files | Participant's existing filesystem; browser reads files locally | No application encryption of the original file | The application does not upload the original Office file or create a persistent draft copy. Existing files remain under participant control |
| Extracted text, editable document names, source filenames and document drafts | Browser/worker RAM; names and extracted text sent to on-premises Web for inference | Plaintext during use; no persisted draft to encrypt | Lost on reload/closure; not placed in localStorage, IndexedDB, SQLite, Firestore or logs |

Successful inference drops its prompt. Terminal output or a failed attempt's retry prompt expires after 10 minutes; result acknowledgement/revocation can dispose it earlier |
| Completed result, analysis ID, analysis workspace version, model name, duration/counts, frozen submission answers and questionnaire reference | Browser RAM while displayed; sealed `analysisResult` in IndexedDB | Web server seals/unseals using `iron-session`; current library defaults are AES-256-CBC with HMAC-SHA-256 integrity protection | Browser persistence only. Owner-bound; explicit deletion, withdrawal, invalid-session cleanup/reset or browser clearing removes the saved value. Seals have no application expiration. Browser bytes remain until explicitly removed |
| Frozen initial-questionnaire recovery answers and definition/analysis IDs | Browser RAM; sealed `recoveredSurvey` in IndexedDB; Web request RAM only during seal/unseal | Web seals/unseals with `iron-session` and binds purpose, consent and session generation. No application expiration | Save before dispatch; reload restores identical retry payload and disables editing. Accepted submission, withdrawal, invalid-session cleanup/reset and explicit recovery clear it. No answers enter SQLite |

| Reset/adoption coordination markers | Browser IndexedDB `aerpp-session-coordination`, version 2, `coordination` store / `state` record | Unencrypted identifiers beside the independently sealed private payloads above | Short transactions check reset/generation and atomically update context/results/retries; no plaintext document, result or email fields |
| PID and consent/withdrawal PDF document ID (DID) | Web generates them; PID is used in SQLite/Firestore; DID is placed in downloaded PDFs | Web/Admin use versioned, domain-separated HMAC-SHA-256 over canonical email inputs with the literal identifier secret, truncated to 128 bits / 32 hexadecimal characters. DID additionally binds Japan date, event purpose and the document-set manifest SHA-256 | Pseudonymous linkage, not anonymization or reversible email encryption. Admin reproduces DIDs for exports and authenticated comparison using the [shared identifier contract](identifiers.md) |
| Result Word download | Generated in browser RAM, saved to participant-selected filesystem | No application file encryption | Explicit download; can contain result text and document excerpts. Application cleanup does not delete downloaded files |
| Consent/withdrawal PDF with email, date and DID | Filled in Web request RAM, downloaded to participant filesystem | PDF is not application-encrypted; DID is hashed on Web | No server persistence of the filled PDF. Supplied blank research assets are separate static inputs |

Browser storage encryption therefore does **not** mean encryption is performed in the browser or that Web cannot read the content. The keys are on Web, and its request/job memory contains plaintext. Document drafts currently have no encrypted browser persistence at all. These distinctions must be preserved in participant/operator descriptions.

## Retention and verification limits

The local LLM request specifies `store: false`; this is not verification of LM Studio's logs, host swap/crash dumps or host backups. The current operational bundle uses local HTTP and relies on host/network restrictions. Confirm the actual on-premises retention and network boundary before participant use; see [operational installation](../infra/BUNDLE-README.md).

Withdrawal deletes live authentication, analysis-attempt and questionnaire records, while retaining consent/withdrawal/recovery audit, participant state, operational run/access history, original/submitting linkage and withdrawal jobs. It does not erase Gmail, exported files, provider backups or operational logs. Browser expiry likewise is not physical browser-storage deletion. The agreed [study closure](study-operations.md#study-closure-and-deletion) removes the Web server/DB at study end and the cloud project after verified Admin extraction. This is an operator procedure, not an application-enforced universal purge; offline/mail/browser copies retain their separate ownership and lifecycle.

Data minimization review should distinguish a necessary retry/audit record from an accidental duplicate. Authentication/email overlap and full `_integrity` answer copies have identified current purposes; reducing their retention or replacing receipts with canonical digests would require separate changes and retry/withdrawal verification. The current withdrawal policy removes research content/measurements while retaining the specified operational facts; it does not reconstruct records already deleted under an earlier policy.

## Research document originals and copies

The [document archive](document-sets.md) holds blank PDF/MDX originals and a canonical manifest, without participant data. Consent/withdrawal records retain their version/hash reference after research deletion. Web/Admin generate personal copies in RAM; they do not persist completed PDFs. Authenticated Admin reissue records only a hashed operator identity, target IDs, set, times and outcome in retained `accessEvents`. File encryption exemptions for participant-held PDFs continue to apply. Document verification does not log the entered email or create a new participant authentication route.
